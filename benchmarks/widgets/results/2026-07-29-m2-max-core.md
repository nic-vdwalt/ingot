# Headless Core Widget Results - 2026-07-29

These results are a dated local measurement, not a universal framework ranking. They measure headless
CPU work for equivalent fixed-geometry benchmark adapters. They do not measure native rendering, GPU
time, presentation, memory, startup, idle power, or the complete application integrations.

This run supersedes [2026-07-26-m2-max-core.md](2026-07-26-m2-max-core.md); see
[Methodology changes](#methodology-changes) for why the two runs are not comparable.

## Environment

- Machine: Apple M2 Max, arm64
- OS: macOS 15.6.1
- Drawable contract: 1280×720, scale factor 1
- Collection: 300 warm-up frames, 2,000 measured frames, seven fresh processes per case
- Ingot: workspace revision `61f4fee`, Odin `dev-2026-06:285f6d87b`
- Dear ImGui: `5d4126876bc10396d4c6511853ff10964414c776` (v1.92.1), Apple clang 17.0.0
- egui: `f2ab57d6987a9b7984f0637cc4d9f2fd173c507c` (0.32.3), Rust 1.90.0
- Run order: randomized by the suite runner
- Validation: 1,358 result records accepted; nominal dropped-output records rejected
- Cross-framework conformance: `state_checksum` agreed across all three frameworks for every
  shared workload and scale - the first run where this held for unique-label workloads

Display refresh and power-mode metadata were not set for this run. Machine load varied over the
roughly seventy-minute collection window; several cases show wide fresh-process spreads for all
three frameworks simultaneously, which is background-load noise, not framework variance. Medians
across the seven fresh-process medians are the accepted values.

## Methodology changes

The 2026-07-26 run compared adapters that did not implement the same work. Four conformance bugs
were fixed before this run (framework pins unchanged; only workspace adapter code changed):

1. **Label format nonconformance (Dear ImGui).** `spec/dataset.json` pins unique labels to
   `Widget %08d`; the Dear ImGui adapter emitted unpadded `"Widget " + std::to_string(i)` -
   shorter strings and cheaper formatting than Ingot and egui produced.
2. **Per-frame label formatting in timed regions (all three).** Frame-invariant labels were
   formatted inside the timed loop, measuring `core:fmt` vs `std::to_string` vs `format!` instead
   of widget submission. Profiling put ~56% of Ingot's `list_full` samples inside `fmt.bprintf`.
   All adapters now precompute a 16,384-entry label table outside the timed region
   (`label_index_modulus` in `spec/dataset.json`).
3. **Divergent churn semantics.** Ingot rotated 100% of label positions every frame; Dear ImGui
   and egui pushed an ID and re-submitted identical labels (zero text churn). The spec's
   `churn_percent: 10` is now pinned as an explicit rule implemented identically by all three:
   position `p` is churned when `(p + frame) % 10 == 0` and draws label `(p + frame) % scale`.
4. **Divergent table cell indexing.** Ingot used `row * 4 % 16384` (one label repeated across a
   row's four columns); Dear ImGui and egui used `row * 4 + column`. All three now use
   `(row * columns + column) % 16384`, pinned in `spec/workloads.json`.

The same change set also removed regressions and per-widget temporary-string copies in Ingot's
paint and measurement hot paths (`ui/draw.odin`, `ui/font.odin`, `ui/widgets.odin`): the pane
screen-coordinate transform now early-outs when no pane scope is active, `size → Font_Id` lookups
are memoized per frame, and label draw/measure paths accept `string` directly instead of cloning
to a temporary cstring per widget per frame.

Because labels, churn content, and table content changed, `state_checksum` values differ from the
2026-07-26 run by design. Cross-framework checksum agreement per workload and scale is the new
conformance oracle and held for the entire run.

## What This Establishes

- With conformant adapters, Ingot led every representative case except the accessibility-button
  case, where Dear ImGui led while emitting no accessibility output (see Limits).
- The unique-text cases (unique labels, full list, unique table cells, churn) moved the most:
  they previously measured adapter string formatting, not framework submission.
- Virtualization kept all three frameworks nearly independent of the one-million-row logical data
  size because only 44 rows were submitted.
- egui took substantially more core CPU time in these adapters, but it also offers a richer layout
  and retained integration model; these numbers do not isolate the cost of individual architectural
  features.

## Limits

The benchmark adapters are intentionally equivalent rather than idiomatic showcase applications.
Dear ImGui has no core accessibility implementation, and the egui accessibility case does not
include an `eframe`/AccessKit host, so accessibility rows are not a complete feature-parity
comparison; Ingot is the only adapter emitting semantics in that case. Paint output also differs
by framework, and headless finalization boundaries are not identical enough to combine into one
cross-framework score.

Re-run the checked-in suite before making release claims on different hardware or revisions. Raw
data for this local run was generated at `/tmp/widget-run-fair.jsonl` and was not committed because
repository policy requires durable artifact hosting and checksums for bulky raw runs.
