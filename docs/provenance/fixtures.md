# Fixture and generated-data provenance

## WSS loopback PKI

`testdata/wss` is a deliberately public, localhost-only test PKI generated for
Ingot's offline TLS matrix. Its private keys are not credentials and must never
be used outside tests. `testdata/wss/README.md` records the safety boundary and
certificate fingerprints. Regenerate the set with the OpenSSL commands recorded
in the Git commit that introduced the fixture, preserving localhost and wrong-
host coverage and updating the fingerprints.

## Static-analysis baselines

`scripts/gfx_context_baseline.json` is generated by
`scripts/check_gfx_context.py` and records existing context-ownership findings;
new findings fail the gate. `scripts/odin_style_baseline.json` is generated by
`scripts/check_odin_style.py` and records only temporary legacy exceptions.
Regenerate either file only after reviewing the corresponding source changes;
baselines may shrink but must not hide new violations.

## Visual and lifecycle fixtures

The sources under `examples/render_fixture`, `examples/multi_context_fixture`,
and `examples/wss_fixture` are original Ingot test programs. They produce no
committed binary output. Build products are ignored and must be regenerated by
the documented testing commands.

## Widget benchmark data

`benchmarks/widgets/manifest.json` pins framework revisions, toolchains, and the
font checksum. Human-readable reports may be committed with their hardware and
revision metadata. Raw generated runs remain external and require a stable
retrieval location and checksum, as specified in
`benchmarks/widgets/results/README.md`.
