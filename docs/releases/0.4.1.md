## Release inventory

- Fixed: the committed Windows libvterm archive now includes all four vendored
  robustness patches (imported from Windows run `38216972728`, artifact
  `11731239833`). `v0.4.0` shipped the upstream-unpatched archive.
- Fixed: libvterm REP no longer loops forever when the saved glyph width is
  zero. Both macOS archives include the fix; see known limitations for Windows.
- Fixed: Fit button overloads route through one canonical implementation per
  tier; `Theme_Tokens` and `Metrics` projection contracts gain field-complete
  tests. No consumer signature changes.
- Maintenance: one `windows_expected_assert_suites` manifest schema drives
  expected-assert isolation and drift checks across gfx, ui and fit, and
  registers four previously missing Fit tests. Windows gfx tests default to one
  runner thread to mitigate an intermittent timeout.

## Known limitations

The committed Windows libvterm archive predates the REP zero-width fix. Windows
CI rebuilds the archive from vendored source before running terminal tests, so a
green run does not validate the archive shipped in this snapshot. Windows
consumers needing the REP fix must rebuild with `scripts/build-libvterm.bat`
before linking. Successful candidate run `38367410585` uploaded a rebuilt
archive (artifact `11796654538`, `windows-libvterm-patched`); committing it,
after checksum verification with `scripts/record-artifact-checksum.py`, is
follow-up work for a later tag.

The exact cause of the intermittent four-thread Windows gfx timeout is not
confirmed; one runner thread is a mitigation. The compiler pin still needs the
documented bounded crash-retry workaround. Native compilation is not
GPU/accessibility/runtime certification. Linux arm64 has no verified prebuilt
AccessKit artifact.
