## Known limitations

The candidate's committed Windows libvterm archive is still upstream-unpatched.
Windows CI performs strict/hygiene checks first, then rebuilds the archive and
tests that replacement. A green run therefore does not validate the archive
shipped in this snapshot. Windows consumers needing the fixes must rebuild from
the vendored sources with `scripts/build-libvterm.bat` in a suitable Windows
build environment before linking.

A separate follow-up must obtain a matching successful Windows build, verify its
artifact/checksum, replace the committed archive, and synchronize provenance and
notices with `scripts/record-artifact-checksum.py`. Test the actual replacement.
All four vendored patches must be included, not just the two named in the stale
manifest note. Shipping that replacement inside v0.4.0 requires approval of a
newer target; it cannot silently change this pin.

The compiler pin still needs the documented bounded crash-retry workaround.
Native compilation is not GPU/accessibility/runtime certification. Linux arm64
has no verified prebuilt AccessKit artifact. Source-only status does not remove
obligations for third-party archives already committed in the tree.
